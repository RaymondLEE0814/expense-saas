# Apple 스타일 디자인 가이드 (사업비 정산 SaaS)

> 사업비 정산 관리 SaaS의 **랜딩(홈페이지)**과 **앱 화면** 모두에 적용한다.
> 디자이너는 모든 화면 명세 작성 시 이 가이드를 1순위 참고로 한다.

---

## 1. 디자인 철학

Apple HIG에서 도출한 3가지 핵심 원칙:

### 1.1 명료성(Clarity)
- 텍스트는 어떤 크기에서도 읽기 쉽다
- 아이콘은 즉시 의미가 전달된다
- 장식은 미묘하고 적절하다
- 기능에 대한 집중이 디자인을 이끈다

### 1.2 일관된 위계(Deference)
- UI가 콘텐츠를 방해하지 않고 보조한다
- 반투명, 블러, 미묘한 그림자로 깊이감을 만든다
- 콘텐츠가 화면 가장자리까지 확장된다는 느낌

### 1.3 깊이(Depth)
- 시각적 레이어와 사실적인 움직임이 위계와 활기를 전달
- 인터랙션에 부드러운 전환(트랜지션) 사용
- 사용자가 위치를 잃지 않도록

## 2. 컬러 시스템

### 2.1 기본 팔레트 (Light Mode)
| 토큰 | 값 | 용도 |
|------|-----|------|
| `--bg-primary` | `#FFFFFF` | 메인 배경 |
| `--bg-secondary` | `#F5F5F7` | 섹션 배경 / 카드 배경 |
| `--bg-tertiary` | `#FAFAFA` | 입력 필드 / 미묘한 구분 |
| `--text-primary` | `#1D1D1F` | 본문 텍스트 (순흑 X) |
| `--text-secondary` | `#6E6E73` | 보조 텍스트 |
| `--text-tertiary` | `#86868B` | 캡션 / 비활성 |
| `--accent-blue` | `#0071E3` | 주요 액션 (Apple Blue) |
| `--accent-blue-hover` | `#0077ED` | 호버 |
| `--divider` | `#D2D2D7` | 구분선 |

### 2.2 시맨틱 컬러
| 역할 | 라이트 | 다크(추후) |
|------|--------|-----------|
| Success | `#34C759` | `#30D158` |
| Warning | `#FF9F0A` | `#FFD60A` |
| Danger  | `#FF3B30` | `#FF453A` |

### 2.3 재원 컬러 (도메인 전용)
- 정부지원금: `#0071E3` (Apple Blue)
- 자기부담현금: `#34C759` (Apple Green)
- 자기부담현물: `#FF9F0A` (Apple Orange)

### 2.4 사용 원칙
- 순흑(`#000`)·순백(`#FFF`)은 메인 배경/순간적 강조에만
- 컬러 사용은 **최소화**, 강조가 필요한 한 곳에만
- 카드/섹션 배경은 미묘한 그레이(`#F5F5F7`)로 깊이 표현

## 3. 타이포그래피

### 3.1 폰트 패밀리
- 영문: `SF Pro Display`, `SF Pro Text`, system-ui fallback
- 한글: `Pretendard`, `-apple-system` fallback
- 숫자(금액): `SF Pro Display` + `font-variant-numeric: tabular-nums`

### 3.2 타입 스케일 (랜딩용)
| 클래스 | 크기 | 굵기 | line-height | 용도 |
|--------|------|------|-------------|------|
| `text-hero` | 80px | 600 | 1.05 | 메인 히어로 헤드라인 |
| `text-display` | 56px | 600 | 1.1 | 섹션 제목 |
| `text-title-1` | 40px | 600 | 1.15 | 페이지 타이틀 |
| `text-title-2` | 32px | 600 | 1.2 | 큰 섹션 |
| `text-title-3` | 24px | 600 | 1.25 | 카드 타이틀 |
| `text-headline` | 20px | 600 | 1.3 | 강조 본문 |
| `text-body` | 17px | 400 | 1.5 | 본문 |
| `text-caption` | 14px | 400 | 1.4 | 캡션 |
| `text-footnote` | 12px | 400 | 1.4 | 부가 정보 |

### 3.3 앱 화면용 (데이터 밀집 화면, 좀 더 컴팩트)
- 본문: 14px / 400
- 헤딩: 20px / 24px / 32px
- 숫자: tabular-nums + 500 weight + 우측 정렬

### 3.4 타이포 사용 원칙
- 한 화면에 폰트 사이즈 종류는 3~4개로 제한
- 굵기는 400(본문) / 500(숫자·강조) / 600(제목)만 사용
- letter-spacing: 제목은 -0.02em, 본문은 0

## 4. 레이아웃 / 그리드

### 4.1 컨테이너
- 최대 너비: **980px** (Apple 표준) 또는 **1200px** (앱 대시보드)
- 좌우 패딩: 모바일 22px / 태블릿 40px / 데스크톱 64px

### 4.2 섹션 간격 (랜딩)
- 큰 섹션 사이: 120px (모바일 80px)
- 섹션 내 요소: 48~64px
- 카드 내부 패딩: 32px

### 4.3 간격 토큰 (4px 베이스)
| 토큰 | 값 |
|------|-----|
| `space-0` | 0 |
| `space-1` | 4px |
| `space-2` | 8px |
| `space-3` | 12px |
| `space-4` | 16px |
| `space-5` | 20px |
| `space-6` | 24px |
| `space-8` | 32px |
| `space-10` | 40px |
| `space-12` | 48px |
| `space-16` | 64px |
| `space-20` | 80px |
| `space-30` | 120px |

### 4.4 라운드(borderRadius)
- 카드: 18px (Apple 카드 표준)
- 큰 카드/모달: 24px
- 버튼: 980px (pill) 또는 12px
- 입력 필드: 12px
- 작은 배지: 6px

### 4.5 그림자 (미묘하게)
```css
--shadow-sm:  0 1px 2px rgba(0,0,0,0.04);
--shadow-md:  0 4px 16px rgba(0,0,0,0.06);
--shadow-lg:  0 8px 30px rgba(0,0,0,0.08);
--shadow-xl:  0 20px 60px rgba(0,0,0,0.1);
```

## 5. 버튼

### 5.1 형태
- **Primary**: 배경 `--accent-blue`, 흰 텍스트, 라운드 980px(pill)
- **Secondary**: 배경 투명, 텍스트 `--accent-blue`, 보더 없음
- **Tertiary**: 배경 `#F5F5F7`, 텍스트 `--text-primary`

### 5.2 크기
| 사이즈 | 높이 | 가로 패딩 | 폰트 |
|--------|------|-----------|------|
| sm | 32px | 16px | 13px |
| md | 40px | 20px | 15px |
| lg | 48px | 28px | 17px |
| xl | 56px | 32px | 17px |

### 5.3 상태
- hover: `--accent-blue-hover`, transition 200ms
- active: 살짝 어둡게 (`--accent-blue-active`)
- disabled: opacity 0.4
- focus: outline 2px `--accent-blue` 50% opacity (접근성)

## 6. 카드 / 컨테이너

```
┌─────────────────────────┐  ← border-radius: 18px
│                          │  ← padding: 32px
│  (콘텐츠)               │  ← background: #FFFFFF or #F5F5F7
│                          │  ← box-shadow: --shadow-md (선택)
└─────────────────────────┘
```

- 보더 사용 자제 → 배경 색 차이로 구분
- 카드 안에 카드 중첩 시 라운드 줄임 (18px → 12px)

---

## 7. 인터랙션 / 모션

### 7.1 트랜지션 기본값
- duration: 200ms (단순) / 400ms (페이지 전환) / 600ms (큰 요소)
- easing: `cubic-bezier(0.4, 0, 0.2, 1)` (ease-out)
- Apple은 `cubic-bezier(0.25, 0.1, 0.25, 1)`도 자주 사용

### 7.2 마이크로 인터랙션
- 버튼 hover: `transform: translateY(-1px)` + shadow 증가
- 카드 hover: shadow만 부드럽게 강화
- 클릭 시: 살짝 scale(0.98)로 눌리는 느낌
- 페이지 진입: opacity + translateY(20px → 0)

### 7.3 스크롤
- 부드러운 스크롤 (smooth)
- 큰 이미지/섹션: 살짝 parallax 가능 (과하지 않게)
- 스크롤 인디케이터는 기본 OS 것 사용

---

## 8. 콘텐츠 / 카피

### 8.1 톤
- 간결, 명료, 자신감
- 기술 용어보다 사용자 가치 우선
- "사업비 정산이 끝납니다" 대신 "10분이면 한 달치 정산이 끝납니다"

### 8.2 헤드라인 패턴
- **Apple 스타일**: 짧고 강한 한 문장 + 부제로 보충
- 예:
  - 헤드: "정산, 다시 간단해집니다."
  - 부제: "3개 회사, 12개 사업, 80개 비목을 한 곳에서."

### 8.3 영문 단어 사용
- 도메인 용어는 한글 우선 (사업비/비목/재원)
- UI 액션은 한글 (저장/취소/추가)

## 9. 랜딩(홈페이지) 섹션 가이드

### 9.1 추천 구조
```
[Nav] - 투명 배경, 스크롤 시 블러 + 흰 배경
  ↓
[Hero] - 80vh, 큰 헤드라인 + 1줄 부제 + CTA 1개 + 우측/하단에 제품 스크린샷
  ↓
[Problem] - "수기 관리의 한계" 시각화
  ↓
[Solution / Features] - 3~4개 카드, 각 카드 = 큰 아이콘 + 제목 + 한 문장
  ↓
[Workflow] - "정부지원 사업 → 비목 → 집행 → 정산" 4단계 시각화
  ↓
[Screenshots] - 큰 데스크톱 mockup 2~3장 (Apple Keynote 스타일)
  ↓
[Pricing] (Phase 3) - 3개 플랜, 가운데 추천
  ↓
[CTA] - "지금 시작하기" 단일 거대 버튼
  ↓
[Footer] - 미니멀, 4열 링크
```

### 9.2 Hero 작성 원칙
- 헤드라인은 **한 줄** (꺾으려면 의도된 줄바꿈)
- 부제는 **한 문장**
- CTA는 **하나**만 (보조 액션은 텍스트 링크)
- 배경은 단색 또는 미묘한 그라데이션
- 제품 이미지: 둥근 모서리 + 미묘한 그림자

---

## 10. 앱 화면(대시보드) 적용 시 변형

랜딩과 달리 데이터 밀집도가 높으므로:
- 본문 17px → **14px**
- 카드 라운드 18px → **12px**
- 섹션 간격 120px → **24~32px**
- 컬러는 더 절제 (회색 톤 강화)
- 단, 타입 위계·여백·미묘한 그림자 원칙은 동일

---

## 11. 금지 사항 (Do NOT)
- ❌ 진한 보더(1px 이상)로 카드 구분
- ❌ 강한 그림자(다크 박스 효과)
- ❌ 한 화면에 컬러 4개 이상 사용
- ❌ 폰트 패밀리 2개 이상 (영문/한글 시스템 폰트 매칭은 OK)
- ❌ 순흑(`#000000`) / 순백 대비
- ❌ 작은 글자(<12px)
- ❌ 모든 모서리 직각 (어떤 컴포넌트라도 살짝 라운드)
- ❌ 과도한 애니메이션 (관심을 빼앗는 모션)

---

## 12. 체크리스트 (디자이너가 화면 명세 종료 전 확인)
- [ ] 컬러 토큰만 사용했는가
- [ ] 폰트 사이즈가 3~4개 이내인가
- [ ] 카드/버튼 라운드가 일관적인가
- [ ] 여백이 충분한가 (특히 모바일)
- [ ] 호버/클릭/포커스 상태가 정의되어 있는가
- [ ] 빈 상태(Empty State)에 일러스트 또는 안내 카피가 있는가
- [ ] 로딩은 스켈레톤(블러 박스)인가
- [ ] 마이크로 카피가 사용자 중심 언어인가
