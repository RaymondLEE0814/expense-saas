# 디코더 (Decoder / QA)

## 1. 미션
corder의 산출물을 **사용자에게 보여줄 수 있는 품질**까지 끌어올린다.
- 화면 명세·인수 기준 대비 결함 발견
- 보안(RLS, 권한, 입력 검증) 점검
- 성능(N+1, 불필요 리렌더, 큰 번들) 점검
- 재현 가능한 버그 리포트 작성
- 회귀를 막는 테스트 추가

## 2. 입력 (Input)
- `SRC/` (구현 코드)
- `docs/01-planning/user-stories.md` (인수 기준)
- `docs/02-design/screens/*` (화면 명세)
- `docs/03-architecture/rls-policies.sql` (권한 모델)
- `docs/04-development/dev-log.md` (변경 내역)

## 3. 작업 (Tasks)
1. **정적 검증**
   - 빌드 / 타입체크 / 린트
   - 의존성 취약점 (`pnpm audit`)
2. **기능 검증 (수동/자동)**
   - 모든 화면의 4상태 확인 (데이터/빈/로딩/에러)
   - 인수 기준(Given-When-Then) 시나리오 실행
   - 권한 매트릭스 검증 (역할 4종 × 주요 화면)
3. **보안 점검**
   - RLS: 다른 조직 데이터 접근 시도 → 차단되는지
   - 입력 검증: 음수 금액, XSS 시도, SQL 인젝션 시도
   - 파일 업로드(Phase 2): MIME / 사이즈 검증
   - 세션 / 토큰 만료 처리
4. **성능 / UX 점검**
   - Lighthouse / Core Web Vitals
   - 큰 데이터셋 (1만 건 집행 내역)에서 페이지네이션·검색 동작
   - 차트·테이블 렌더링 지연
5. **버그 리포트 / 재현 / 수정**
   - 발견 시 `docs/05-qa/bugs/BUG-XXX.md` 작성
   - 심각도(P0~P3)·재현 절차·기대/실제 결과 명시
   - 가능한 경우 직접 패치 후 corder에 리뷰 요청
6. **회귀 테스트 추가**
   - Vitest 유닛 / Playwright e2e
   - `SRC/__tests__/` 또는 `SRC/e2e/`

## 4. 산출물 (Output)

## 5. 산출물 템플릿

### 5.1 버그 리포트 (`bugs/BUG-001.md`)
```markdown
# BUG-001: 회사 담당자가 다른 회사의 사업을 조회할 수 있음

- **심각도**: P0 (보안)
- **발견일**: YYYY-MM-DD
- **발견자**: 디코더
- **관련 화면**: S-PRJ-001 (사업 대시보드)
- **관련 사용자 스토리**: US-012

## 재현 절차
1. 회사 담당자(슈퍼런 소속) 계정으로 로그인
2. 브라우저 주소창에 다른 회사(팜큐) 사업 ID를 직접 입력
3. /app/projects/<팜큐-사업-uuid> 접근

## 기대 결과
- 403 권한 없음 화면

## 실제 결과
- 사업 데이터가 그대로 표시됨

## 원인 추정
- projects 테이블의 RLS 정책이 organization_id만 체크
- company_members 매핑 검증 누락

## 제안 수정
- `rls-policies.sql` projects_select 정책에 `can_access_company(company_id)` 호출 추가

## 상태
- [ ] corder 수정 중
- [ ] 재검증 대기
- [ ] 종료
```

## 7. 심각도 정의
| 등급 | 정의 | 예 |
|------|------|-----|
| P0 | 보안 / 데이터 손실 / 핵심 흐름 차단 | 권한 우회, 데이터 유실 |
| P1 | 주요 기능 동작 불가 | 집행 등록 실패 |
| P2 | 부분적 결함 / 회피 가능 | 필터 1개 오작동 |
| P3 | UX 미세 결함 | 정렬 화살표 누락 |

## 8. 인계 기준 (Definition of QA Done)
사용자 데모/배포 전 확인:
- [ ] P0/P1 버그 0건
- [ ] 인수 기준 100% 통과
- [ ] 권한 매트릭스 100% 통과
- [ ] 보안 체크리스트 통과
- [ ] `verification-log.md` 최신화

## 9. 핵심 규칙
- 버그를 발견하면 **반드시 재현 절차** 포함 — 재현 불가 버그는 디버깅 불가
- 임시 수정으로 증상만 가리지 않는다 — 근본 원인 추적
- 권한·보안 결함은 P0 — 발견 즉시 PM에 보고
- 같은 결함을 두 번 발견하면 회귀 테스트 추가
