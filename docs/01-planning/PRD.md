# PRD — 사업비 정산 관리 SaaS

> 작성자: 기획자 | 일자: 2026-05-19 | 버전: v1.0
> 상위 문서: [worklist.md](../../worklist.md)

---

## 1. 제품 비전

**"정부지원 사업비를 운영하는 모든 스타트업이, 엑셀이 아닌 도구로 정산하게 한다."**

정부지원 사업을 수행하는 스타트업·법인이 사업비를 **실시간으로 추적**하고, 사업 종료 시점에 **수기·엑셀 없이 정산 보고**를 마칠 수 있도록 한다. 다수 법인을 운영하는 그룹사의 통합 관리도 지원한다.

---

## 2. 해결하려는 문제

| 문제 | 현재 상태 | 결과 |
|------|----------|------|
| **분산된 관리** | 회사·사업·재원·비목이 여러 엑셀에 흩어짐 | 합산·집계 시 수기 작업 다수, 오류 빈번 |
| **실시간성 부족** | 월말·정산 직전에야 집행률 파악 | 비목 잔여액 파악 불가 → 초과 집행·이월 |
| **권한·격리 부재** | 엑셀에 모든 데이터 → 회사 담당자가 다른 회사 정보까지 봄 | 정보 분리 불가, 외부 회계사 협업 어려움 |
| **정산 양식 변환** | 주관기관 양식에 맞춰 매번 수기 변환 | 정산 직전 야근, 반복 작업 |

## 3. 타겟 사용자 (1차)

| 분류 | 설명 | 우선순위 |
|------|------|---------|
| **자사(안티그래비티 그룹)** | 리피치 / 슈퍼런 / 팜큐 3법인 통합 관리 | P0 — 즉시 사용 |
| **유사 그룹사** | 2~5개 법인을 운영하며 정부지원 사업 다수 수행 | P1 — Phase 2 베타 |
| **단일 스타트업** | 1개 법인, 1~3개 사업 진행 | P2 — Phase 3 SaaS |

## 4. 성공 지표 (KPI)

### 4.1 Phase 1 (자사 적용)
- 3개 법인의 **모든** 현행 사업이 본 시스템에 등록됨 (수 기준)
- 월말 정산 회의 준비 시간: **기존 대비 50% 단축**
- 비목 초과 집행 사고: **0건/분기**

### 4.2 Phase 2 (베타)
- 외부 조직 가입 수: **5개 이상**
- 베타 이탈률: **20% 이하**

### 4.3 Phase 3 (퍼블릭)
- 월 활성 조직(MAU-Org) 추이
- 유료 전환율 / 평균 ARPU

## 5. 제품 범위 (Scope)

### 5.1 ✅ In Scope (MVP)
1. 멀티 테넌트 인증/회원가입 (이메일)
2. 조직 생성 + 멤버 초대 + 역할 관리
3. 회사 CRUD
4. 사업 CRUD (기간·총사업비·재원)
5. 비목 CRUD (계획 금액)
6. 집행 내역 CRUD
7. 사업/회사/조직 대시보드 (집행률·재원·D-day)
8. 엑셀 내보내기
9. 권한 모델 (조직관리자 / 회사담당자 / 조회자)

### 5.2 ⛔ Out of Scope (MVP 제외)
- 증빙 파일 첨부 (Phase 2)
- 소셜 로그인 (Phase 2)
- 정산 양식 자동 생성 (Phase 2)
- 통장 거래 자동 매칭 (Phase 2)
- 알림 (메일/카카오톡, Phase 2)
- 결제/구독 (Phase 3)
- 슈퍼관리자 운영 콘솔 (Phase 3)
- 모바일 앱 (Phase 3+)
- 다국어 (Phase 3+)

## 6. 핵심 기능 (MoSCoW)

### 6.1 Must Have (MVP)
| ID | 기능 | 비고 |
|----|------|------|
| M-01 | 이메일 회원가입 / 로그인 / 비밀번호 재설정 | Supabase Auth |
| M-02 | 조직 생성 + 슬러그 설정 | 가입자 = org_admin 자동 부여 |
| M-03 | 멤버 초대 + 역할 부여 (org_admin/company_member/viewer) | 이메일 토큰 링크 |
| M-04 | 회사(법인) 등록·수정·삭제 | 사업자번호 검증 |
| M-05 | 사업 등록·수정·종료 처리 | 기간·총사업비·재원 |
| M-06 | 재원 구성 (정부지원금 / 자기부담현금 / 자기부담현물) | 합계 = 총사업비 검증 |
| M-07 | 비목 등록·수정·삭제 + 계획 금액 | 정렬 순서 지정 |
| M-08 | 집행 내역 등록·수정·삭제 | 일자/비목/재원/금액/거래처/적요 |
| M-09 | 조직 대시보드 (전 회사 요약) | KPI 카드 + 회사별 카드 |
| M-10 | 사업 대시보드 (집행률·재원·D-day·월별 추이) | 핵심 분석 화면 |
| M-11 | 집행 내역 목록 + 필터 + 페이지네이션 | 회사·사업·비목·기간·재원 |
| M-12 | 엑셀(XLSX) 내보내기 | 사업별·비목별 |
| M-13 | RLS 기반 조직·회사 격리 | 보안 핵심 |

### 6.2 Should Have (Phase 2)
- S-01 증빙 파일 첨부 (Supabase Storage)
- S-02 소셜 로그인 (Google)
- S-03 알림 (이메일: 사업 종료 D-30/D-7, 비목 95% 초과)
- S-04 정산 보고서 PDF 출력

### 6.3 Could Have (Phase 3)
- C-01 정산 양식 자동 생성 (주관기관별)
- C-02 통장 거래 import + 자동 매칭
- C-03 결제/구독 + 슈퍼관리자 콘솔
- C-04 모바일 앱

### 6.4 Won't Have (당분간)
- W-01 회계 시스템(더존 등) 직접 연동
- W-02 다국어
- W-03 온프레미스 배포

## 7. 사용자 흐름 (Hero Flows)

### 7.1 신규 가입 → 첫 사업 등록 (조직 관리자)
회원가입 → 이메일 인증 → 조직 생성 → 회사 등록 → 사업 등록 → 재원·비목 설정 → 집행 입력 시작

### 7.2 일상 사용 (회사 담당자)
로그인 → 본인 회사 사업 진입 → 집행 내역 탭 → 추가 → 대시보드 갱신 확인

### 7.3 월말 정산 (조직 관리자)
조직 대시보드 → 사업별 점검 → 리포트 → 사업·기간 선택 → 엑셀 다운로드

## 8. 비기능 요구사항 (NFR)

### 8.1 보안
- 모든 도메인 테이블에 Postgres RLS 적용
- 조직 간 데이터 완전 격리 (cross-org 접근 시 403)
- 비밀번호: Supabase Auth bcrypt (자체 관리 X)
- Service Role Key: 서버 사이드 어드민 작업에만, 클라이언트 노출 금지

### 8.2 성능
- TTI < 2초 (3G 회선 기준 대시보드)
- 집행 내역 1만 건 페이지네이션 < 500ms
- Lighthouse Performance 점수 ≥ 85 (데스크톱)

### 8.3 사용성
- 한국어 기본 (다국어 X)
- 모바일 반응형 (조회 위주)
- 디자인 가이드: [.agents/skills/design_apple.md](../../.agents/skills/design_apple.md) 1순위 준수
- 색 대비: WCAG AA 이상

### 8.4 데이터
- 시간: 모두 `timestamptz`로 UTC 저장, 표시 시 KST 변환
- 금액: 원 단위 정수 (`numeric(15,0)`), 천 단위 콤마 표시
- 백업: Supabase 자동 백업 + 월 1회 수동 export (조직 단위 JSON/XLSX)

### 8.5 확장성
- 조직당 회사 ~50개, 사업 ~500개, 집행 건 ~10만 건 까지 무리없이 동작
- DB 인덱스: `(organization_id, ...)` 복합 인덱스 우선

## 10. 제약 조건

- **개발 인원**: AI 에이전트 파이프라인 + 사용자 1인 검토
- **예산**: Vercel + Supabase 무료 플랜 시작, 사용량 증가 시 유료 전환
- **일정**: M1(자사 가동)까지의 명시적 데드라인은 없으나 빠를수록 좋음
- **언어**: 한국어 단일, 영문은 코드/식별자에만
