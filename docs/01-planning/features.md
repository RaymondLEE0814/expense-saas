## F-001: 회원가입

**개요**: 신규 사용자가 이메일·비밀번호로 가입한다.

**입력**
| 필드 | 타입 | 필수 | 유효성 |
|------|------|------|--------|
| 이메일 | string | ✔ | RFC 5322, 최대 254자 |
| 비밀번호 | string | ✔ | 8자 이상, 영문+숫자 각 1자 이상 |
| 이름 | string | ✔ | 1~50자 |
| 약관 동의 | boolean | ✔ | true 필수 |

**처리**
1. 클라이언트 검증 → Supabase Auth signup
2. `profiles` 레코드 생성 (id, email, full_name)
3. 인증 메일 자동 발송
4. "이메일을 확인해주세요" 안내 페이지로 이동

**예외**
- 중복 이메일 → 409, "이미 가입된 이메일입니다"
- 검증 실패 → 400, 인라인 에러

**보안**
- 비밀번호는 Supabase Auth에서 bcrypt 해시 (서버 보관 X)
- 가입 시 RLS 미적용 영역(`auth.users`)만 작성

## F-002: 로그인 / 로그아웃

**개요**: 가입한 사용자가 세션을 획득·해제한다.

**입력 (로그인)**
| 필드 | 타입 | 필수 | 유효성 |
|------|------|------|--------|
| 이메일 | string | ✔ | - |
| 비밀번호 | string | ✔ | - |

**처리 (로그인)**
1. Supabase Auth signInWithPassword
2. 세션 쿠키 설정
3. 멤버십 조회 → 활성 조직이 1개면 그곳으로, 여러 개면 마지막 사용 조직, 0개면 `/app/onboarding`

**처리 (로그아웃)**
- Supabase Auth signOut
- 세션 쿠키 삭제 후 `/login`

**예외**
- 잘못된 자격증명 → "이메일 또는 비밀번호가 올바르지 않습니다" (구체 사유 노출 X)
- 미인증 계정 → "이메일 인증이 필요합니다" + 재전송 버튼

## F-003: 비밀번호 재설정

**개요**: 이메일 기반 재설정 토큰 발급.

**처리**
1. `/forgot-password`에서 이메일 입력 → Supabase Auth resetPasswordForEmail
2. 토큰 링크 메일 발송
3. 링크 클릭 → 새 비밀번호 입력 → updateUser

**검증**
- 새 비밀번호: F-001과 동일
- 토큰 만료: Supabase 기본(1시간) 사용

## F-004: 조직 생성

**개요**: 사용자가 새 조직(테넌트)을 만든다.

**입력**
| 필드 | 타입 | 필수 | 유효성 |
|------|------|------|--------|
| 조직명 | string | ✔ | 1~100자 |
| 슬러그 | string | ✔ | `^[a-z0-9-]{3,40}$`, 글로벌 unique |
| 사업자번호 | string | | 10자리, 체크섬 검증 (경고 수준) |

**처리**
1. 슬러그 중복 검사 (debounced)
2. `organizations` INSERT
3. 본인을 `org_admin` 역할로 `memberships` INSERT (status='active')
4. 조직 컨텍스트 쿠키 설정 후 `/app` 이동

## F-007: 멤버 초대

**입력**
| 필드 | 타입 | 필수 | 유효성 |
|------|------|------|--------|
| 이메일 | string | ✔ | RFC 5322 |
| 역할 | enum | ✔ | org_admin / company_member / viewer |
| 회사 | uuid[] | ⚠️ | role=company_member 일 때 최소 1개 필수 |

**처리**
1. 같은 조직 내 이메일 중복 체크
2. 초대 토큰 생성 (랜덤 32자, DB 또는 Supabase Auth signUp + invite)
3. `memberships` INSERT (status='invited', invited_email, invited_by)
4. role=company_member 시 회사 매핑 PRE-INSERT (수락 시 활성)
5. 초대 메일 발송 (만료 7일)

**예외**
- 이미 활성 멤버 → 409
- company_member인데 회사 미선택 → 400

## F-008: 초대 수락

**처리** (시나리오별)
1. **미가입자**: 토큰 검증 → 가입 화면(이메일 prefill) → 가입 완료 시 자동으로 멤버십 active 처리
2. **가입자(미로그인)**: 토큰 검증 → 로그인 → 같은 이메일이면 자동 수락
3. **가입자(로그인)**: 수락 확인 화면 → [수락] 클릭 시 active

**검증**
- 토큰 만료(7일) → 에러
- 토큰 이메일과 로그인 이메일 불일치 → 에러

## 횡단 관심사 (Cross-Cutting)

### 입력 검증 정책
- 클라이언트: 즉시 피드백 (Zod 스키마)
- 서버 액션: 동일 Zod 스키마 재사용 (single source of truth)
- DB: CHECK 제약 + NOT NULL

### 에러 표시
- 인라인 (필드 단위)
- 토스트 (액션 결과 — 저장됨, 실패 등)
- 풀페이지 (권한 없음 / 404 / 500)

### 시간대
- DB: UTC (`timestamptz`)
- 표시: Asia/Seoul (KST)
- 입력 date: 로컬 캘린더 → UTC 자정으로 변환 (또는 date 타입 그대로 유지)

### 금액 표시
- 원 단위 정수 저장
- 표시: 천 단위 콤마, "₩" prefix 또는 "원" suffix (디자이너 결정)

### 빈 상태 (Empty State) 카피
